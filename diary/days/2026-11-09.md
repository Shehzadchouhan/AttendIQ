## Tasks Done

I started the attendance system repository by writing the initial system specification and defining the data models for users, students, batches, and attendance sessions in `README.md`. I implemented the FastAPI backend foundation with SQLAlchemy 2.0 and applied Alembic migrations `0001_initial_schema` and `0002_add_batch_teacher_and_attendance_fields`. I built user authentication using bcrypt password hashing and JWT access tokens, enforcing role-based access control for administrators and teachers via FastAPI dependencies. On the frontend, I scaffolded a React 18 single-page application using Vite, configuring Axios interceptors, protected routing, and management pages for students and batches. Next, I integrated InsightFace (`buffalo_l`) using ONNX Runtime CPU for in-memory face detection and 512-dimensional vector embedding extraction. I applied Alembic migration `0003_student_face_consent` to support consent tracking designed with DPDP Act principles in mind (consent tracking, in-memory processing, no biometric images stored), built face enrollment and verification endpoints, and wrote unit tests for the face engine.

## Problems Faced & Design Decisions

<!-- REVIEW: Sheh to confirm he can explain this -->

1. **Image Orientation and Color Space Handling**: Browser uploads and smartphone cameras submit RGB images that often contain EXIF rotation metadata, whereas InsightFace expects BGR arrays. I added image normalization in `backend/app/services/face_engine.py` using Pillow's `ImageOps.exif_transpose()` to correct orientation and converted the buffer to BGR via OpenCV in memory without disk persistence.
2. **Single-Face Validation for Enrollment**: To prevent corrupted biometric embeddings during student enrollment, an image with multiple people or no detected face must not be saved. I added validation logic in `face_engine.py` that verifies the detected face count and raises an HTTP 400 error unless exactly one face is detected.

## Learnings

* How to deploy ONNX Runtime with `CPUExecutionProvider` to execute ArcFace and RetinaFace neural networks on commodity CPU hardware without requiring dedicated GPUs.
* How to process biometric data ephemerally in memory using `io.BytesIO` following DPDP Act principles (consent tracking, in-memory processing, no biometric images stored).
