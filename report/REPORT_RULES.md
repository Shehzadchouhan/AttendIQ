# GNDEC Training Report Guidelines & Formatting Rules (TR-103)

This document establishes the mandatory formatting, typographical, organizational, and structural rules for the **B.Tech 4-Week Training Report (TR-103)**, prescribed by the **Department of Computer Science and Engineering, Guru Nanak Dev Engineering College, Ludhiana**.

> [!IMPORTANT]
> **Every subsequent task, chapter drafting, table formatting, figure captioning, and final compilation MUST strictly adhere to the standards outlined in this specification.**

---

## 1. General Document Specifications

| Parameter | Mandatory Requirement |
| :--- | :--- |
| **Language & Dialect** | English (British) — e.g., *colour*, *customise*, *centre*, *behaviour*, *modelled*. |
| **Paper Size** | Standard A4 size paper (210 mm $\times$ 297 mm), printed on one side only. |
| **Primary Font Family** | Times New Roman (TNR) throughout the entire report. |
| **Body Text Sizing & Spacing**| Font Size: **12 pt** \| Line Spacing: **Double Spacing** (2.0 line spacing). |
| **Text Alignment** | Justified body paragraphs with standard paragraph indents. |
| **Hard Binding Color** | **Lemon (Yellow)** for TR-103 (Four Weeks Training) with black printed text on cover.<br/>*(TR-102 uses Light Red; initial internal evaluation submission may be spiral bound).* |

## 4. Numbering Schemes & Conventions

### 4.1 Headings and Subheadings
- Follows chapter-prefixed hierarchical decimal numbering:
  - Chapter 1: Headings `1.1`, `1.2`, `1.3` $\dots$ Subheadings `1.1.1`, `1.1.2`, `1.2.1` $\dots$
  - Chapter 2: Headings `2.1`, `2.2` $\dots$ Subheadings `2.1.1`, `2.2.1` $\dots$
  - Chapter 3: Headings `3.1`, `3.2` $\dots$ Subheadings `3.1.1`, `3.2.1` $\dots$
  - (Continuing identically for all chapters).

### 4.2 Tables
- **Numbering**: `Table 1.1`, `Table 1.2` in Chapter 1; `Table 2.1`, `Table 2.2` in Chapter 2; etc.
- **Font & Spacing**: Times New Roman, **10 pt**, **Single Spacing** between rows.
- **Decimal Representation**: Decimals must be indicated by a full stop (`.`), e.g., `75.0%`, not a comma.
- **Caption Placement**: Placed strictly at the **TOP** of the table, **centre aligned**, in Times New Roman, *Italics*, **10 pt**.
  - Example:  
    *Table 2.1 Hardware and Software Specifications*

### 4.3 Figures and Diagrams
- **Numbering**: `Figure 1.1`, `Figure 1.2` in Chapter 1; `Figure 2.1`, `Figure 2.2` in Chapter 2; etc.
- **Background**: Diagrams must be printed on a **white or light background** (dark-themed full diagrams must be inverted or rendered on light canvas for printing clarity).
- **Caption Placement**: Placed strictly at the **BOTTOM** of the figure, **centre aligned**, in Times New Roman, *Italics*, **10 pt**.
  - Example:  
    *Figure 3.1 FaceMark System Architecture & Biometric Pipeline*

### 4.4 Mathematical Equations
- **Numbering**: Right-aligned parenthesized chapter-prefixed numbers: `(1.1)`, `(1.2)` in Chapter 1; `(2.1)` in Chapter 2; `(3.1)` in Chapter 3; etc.
  - Example:
    $$\text{Cosine Similarity} = \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\| \|\mathbf{v}\|} \tag{3.1}$$

## 5. Report Structure & Order of Contents

The report must be assembled in the exact sequence mandated by the GNDEC guidelines:

### 5.1 Preliminary Pages (Front Matter — Numbered in Lowercase Roman Numerals)
1. **Outer Cover Page** (Hardbound Lemon cover with black text)
2. **Inner Title Page** (Identical to outer cover layout on plain paper)
3. **Certificate by Company / Industry** (Sample Sheet format on company letterhead, Page *i*)
4. **Candidate's Declaration** (Standard GNDEC declaration format, Page *ii*)
5. **Abstract** (Summary of project, methodology, and results — **Strictly max 1 page**, Page *iii*)
6. **Acknowledgement** (Formal gratitude to Principal, HoD CSE, Supervisor, Faculty, Page *iv*)
7. **About the Company** (Techversys Solutions Pvt. Ltd., profile and domain, Page *v*)
8. **List of Figures** (Fig. No., Figure Description, Page No., Page *vi*)
9. **List of Tables** (Table No., Table Description, Page No., Page *vii*)
10. **Definitions, Acronyms and Abbreviations** (Alphabetical glossary of terms, Page *viii*)
11. **Table of Contents** (Complete chapter and section outline with page numbers, Page *ix*)

### 5.2 Main Body Chapters (Numbered in Arabic Numerals 1, 2, 3...)
- **CHAPTER 1: INTRODUCTION**
  - 1.1 Introduction to Organization *(Strictly max 3 pages including figures)*
  - 1.2 Introduction to Project
  - 1.3 Project Category *(Application & System Development)*
  - 1.4 Objectives
  - 1.5 Problem Formulation
  - 1.6 Identification / Reorganization of Need
  - 1.7 Existing System
  - 1.8 Proposed System
  - 1.9 Unique Features of the System
- **CHAPTER 2: REQUIREMENT ANALYSIS AND SYSTEM SPECIFICATION**
  - 2.1 Feasibility Study (Technical Feasibility, Economical Feasibility, Operational Feasibility)
  - 2.2 Software Requirement Specification (SRS) Document:
    - Data Requirements
    - Functional Requirements
    - Performance Requirements
    - Dependability Requirements
    - Maintainability Requirements
    - Security Requirements
    - Look and Feel Requirements
  - 2.3 Validation
  - 2.4 Expected Hurdles
  - 2.5 SDLC Model to be Used (Iterative / Agile Methodology)
- **CHAPTER 3: SYSTEM DESIGN**
  - 3.1 Design Approach (Object-Oriented Design & Microservice Architecture)
  - 3.2 Detail Design
  - 3.3 Structured Analysis & Design Tools (System Architecture, DFD Level 0/1/2, Flowcharts, UML Use Case, Sequence & Class Diagrams)
  - 3.4 User Interface Design (Component hierarchy, design tokens, wireframes)
  - 3.5 Database Design:
    - 3.5.1 ER Diagrams
    - 3.5.2 Normalization (1NF, 2NF, 3NF, BCNF analysis)
    - 3.5.3 Database Manipulation (CRUD operations)
    - 3.5.4 Database Connection Controls and Strings (SQLAlchemy Session pooling)
  - 3.6 Methodology & Algorithmic Pipeline (RetinaFace, ArcFace, Cosine Distance, Greedy Bipartite Matching)
- **CHAPTER 4: IMPLEMENTATION, TESTING AND MAINTENANCE**
  - 4.1 Introduction to Languages, IDEs, Tools and Technologies (Python, FastAPI, InsightFace, PostgreSQL, React, Vite, Docker)
  - 4.2 Coding Standards of Languages Used (PEP 8 for Python, ESLint / AirBnB for React JSX)
  - 4.3 Project Scheduling (Gantt Chart & PERT representation across 4-week training)
  - 4.4 Testing Techniques and Test Plans (Unit Testing, Integration Testing, RBAC Security Testing, Biometric Consent Revocation Purge Tests, Coverage Reports $\ge 70\%$)
- **CHAPTER 5: RESULTS AND DISCUSSIONS**
  - 5.1 User Interface Representation (Module-by-module walkthrough)
    - 5.1.1 Brief Description of Various Modules of the System
  - 5.2 Snapshots of System with Brief Detail of Each (Figure 5.1 to Figure 5.9)
  - 5.3 Back Ends Representation (PostgreSQL Database Schema)
    - 5.3.1 Snapshots of Database Tables with Brief Description (Table structures, constraints, audit logs)
- **CHAPTER 6: CONCLUSION AND FUTURE SCOPE**
  - 6.1 Conclusion *(Strictly max 2 pages)*
  - 6.2 Future Scope *(Strictly max 2 pages)*

### 5.3 Post-Body Matter
- **References / Bibliography** (Strictly formatted in GNDEC/IEEE citation standard)
- **Appendix** (Source code highlights, API endpoints list, database seed scripts)
- **Annexures** (Annexure-I: Training Confirmation Letter; Annexure-II: Training Completion Certificate; Annexure-III: Daily Diary extract / GitHub Pages link)

## 6. Citation & Reference Guidelines (GNDEC / IEEE Style)

### 6.1 In-Text Citation Rules
- Citations must appear on the line in square brackets inside the punctuation:
  - As demonstrated by Brown [4], [5].
  - As discussed in prior literature [2], [4]–[7], [9].
  - Use *et al.* when there are three or more authors (e.g. Wood *et al.* [7]).
  - Citations can be treated as nouns: "As proved in [3] and demonstrated in [6]."

### 6.2 Reference List Formatting
- Reference numbers are flush left, enclosed in square brackets `[1]`, `[2]`, forming their own column.
- Author names: First name initialized, followed by last name (e.g. `J. K. Author`).
- Authors separated by commas, with "and" before the final author.
- Examples by material type:
  - **Books**:  
    `[1] B. Klaus and P. Horn, Robot Vision. Cambridge, USA: MIT Press, 1986.`
  - **Conference Papers**:  
    `[2] J. Deng, J. Guo, N. Xue, and S. Zafeiriou, "ArcFace: Additive angular margin loss for deep face recognition," in IEEE/CVF Conference on Computer Vision and Pattern Recognition (CVPR), Long Beach, CA, USA, 2019, pp. 4690–4699.`
  - **Periodicals / Journals**:  
    `[3] R. E. Kalman, "New results in linear filtering and prediction theory," Journal of Electrical Engineering, vol. 83, no. 5, pp. 95–108, Mar. 1961.`
  - **Online Documentation / Standards**:  
    `[4] S. Ramirez. (2024). FastAPI Documentation [Online]. Available: https://fastapi.tiangolo.com`
